# MundoZ Land Protection

MundoZ Land Protection is the main protection and gameplay rules mod for the MundoZ Minecraft server.

It is a server-side Fabric mod responsible for land claims, anti-grief protections, villager safety, PvP arena rules, protected server regions, claim visualization, and the Dragon Egg gameplay system.

This project started as a land claim mod, but evolved into one of the core systems that defines how survival gameplay works on MundoZ.

## Core Philosophy

MundoZ is PvE by default.

Players should be able to build, trade, store items, protect villagers, and play survival without being forced into unwanted PvP or griefing situations.

PvP is supported, but it should happen in designated arenas instead of everywhere in the survival world.

A global PvP opt-in system was tested during development and later removed because it negatively affected normal vanilla survival gameplay. The current design keeps normal survival safe and makes PvP arena-based.

## Claim System

Players can create protected areas with `/claim`.

A normal claim protects a square area centered on the player.

Current claim size:

- 30 blocks in each horizontal direction
- Full vertical protection from Y -64 to Y 320
- Dimension-aware protection

This means claims in different dimensions do not conflict with each other.

The claim system protects player builds from unauthorized:

- breaking
- placing
- interacting
- stealing
- fluid griefing
- entity griefing

## Claim Limits

Players have a limited number of claims.

The claim limit is controlled in `ClaimManager`.

This prevents one player from claiming too much of the world.

## Spawn Protection

Claims cannot be created too close to spawn.

Current spawn protection radius:

- 100 blocks

This keeps the spawn area available for public/server use.

## Structure Protection

The mod checks for protected/generated structures before allowing a claim.

This helps prevent players from claiming important public structures generated by the game.

## Permission System

MundoZ Land Protection has two permission levels:

### Trusted Players

Trusted players are allowed to interact more deeply with a claim.

Typical use:

- friends
- base partners
- trusted builders

Commands:

- `/trust <player>`
- `/untrust <player>`
- `/trustlist`

### Guests

Guests are a lighter permission level.

Typical use:

- visitors
- temporary access
- limited interaction

Commands:

- `/guest <player>`
- `/unguest <player>`
- `/guestlist`

## Player Commands

### `/claim`

Creates a new claim centered on the player.

### `/disclaim`

Removes the claim the player owns at their current position.

### `/claimlocation`

Lists the player's claims and their center coordinates.

### `/trust <player>`

Grants trust permission to another player inside the current claim.

### `/untrust <player>`

Removes trust permission from a player.

### `/trustlist`

Shows trusted players for the current claim.

### `/guest <player>`

Grants guest permission to another player inside the current claim.

### `/unguest <player>`

Removes guest permission from a player.

### `/guestlist`

Shows guest players for the current claim.

### `/claimshow`

Shows the current claim boundaries using particles.

### `/claimhide`

Stops showing the current claim boundaries.

## Claim Visualization

The claim visualization system shows the borders of a claim using particles.

It does not place real blocks in the world.

This allows players to inspect claim boundaries without modifying terrain.

The visualization is automatically disabled when the player stays outside the claim for too long.

## Administrative Commands

### `/claimadmin here`

Shows information about the claim at the admin's current position.

It displays:

- claim type
- server claim status
- arena status
- owner UUID
- dimension
- center position
- boundaries
- trust list
- builder list

### `/claimadmin listall`

Lists all registered claims.

### `/claimadmin remove <number>`

Removes a claim by its list number.

### `/claimadmin tp <number>`

Teleports the admin to a claim by its list number.

### `/claimadmin removehere`

Removes the claim at the admin's current position.

## Server Claims

Server claims are protected regions owned by the server/admin layer instead of normal players.

They are useful for:

- spawn areas
- public builds
- event areas
- coliseums
- arenas
- server infrastructure

## Coliseum System

The coliseum system creates a large protected server area.

Command:

- `/colizeu`

Current coliseum size:

- 50 blocks in each direction
- 50 blocks upward
- 50 blocks downward

The coliseum is a protected server claim, but it is not marked as a PvP arena by default.

## Coliseum Builder System

The mod supports builder permissions for coliseum/server claims.

This allows specific players to build inside protected server regions without giving them OP.

Commands:

- `/colizeubuilder <player>`
- `/colizeuunbuilder <player>`

This is useful for letting trusted builders help with server structures while keeping the region protected.

## Arena System

The arena system creates special PvP regions.

Command:

- `/arena`

Current arena size:

- 10 blocks in each direction
- 10 blocks upward
- 10 blocks downward

Arenas are server claims marked as PvP-enabled areas.

Inside arenas:

- PvP is allowed
- arena-specific death behavior can apply
- keep-inventory style behavior is supported

Outside arenas, normal survival rules apply.

## PvP Protection

The current PvP design is simple:

- PvP is blocked inside normal player claims
- PvP is allowed inside arenas
- Global `/pvp on` and `/pvp off` gameplay was removed

This keeps survival gameplay predictable.

Players do not need to understand complicated combat states to stay safe.

## Villager Protection

Villager protection is one of the most important features of the mod.

Villagers are valuable survival assets.

The mod protects villagers from unauthorized damage and hostile player behavior inside protected areas.

This helps prevent:

- villager killing
- trade hall griefing
- village destruction
- economy disruption
- player base sabotage

## Entity Protection

The mod also protects important entities and interactions inside protected areas.

This helps prevent players from damaging or manipulating things that belong to someone else's claim.

## Block Protection

The mod protects claimed areas from unauthorized block breaking and block placing.

This includes:

- breaking blocks
- placing blocks
- interacting with protected blocks
- modifying another player's base

## Use Protection

The mod protects block interactions inside claims.

This is used for things like containers, doors, utility blocks, and other interactable objects depending on the permission rules.

## Fluid Protection

Fluid griefing is blocked.

This prevents unauthorized use of:

- water
- lava

inside or around protected areas.

Fluid griefing is especially dangerous because it can damage builds indirectly.

## Explosion Protection

The mod includes explosion protection through mixins.

This helps prevent protected builds from being damaged by explosion-based griefing.

## Projectile Protection

Projectile-related protection is handled through mixins and event handlers.

This helps protect entities and protected areas from indirect damage.

## Arena Keep Inventory

The mod includes arena-specific death/drop behavior.

This allows PvP arenas to exist without turning every arena death into a full item loss.

The goal is to support casual PvP without damaging the player's normal survival progress.

## Dragon Egg System

The Dragon Egg system turns the Dragon Egg into a persistent server objective.

Instead of being just a trophy item, the egg becomes a special gameplay object.

The system tracks:

- whether the egg is waiting for the next dragon kill
- whether it was dropped
- whether it was placed
- whether a player is carrying it
- last known position
- last known dimension
- current or previous carrier

## Dragon Egg Gameplay

The Dragon Egg can behave like a capture-the-flag objective.

General flow:

1. The Dragon Egg becomes available.
2. A player obtains or carries it.
3. The server tracks the carrier.
4. Other players can locate the egg.
5. The egg remains part of the server's long-term gameplay.

This creates conflict and exploration around a rare item without requiring global PvP.

## Dragon Egg Commands

### `/dragoneggloc`

Shows the current or last known Dragon Egg location.

If a player is carrying the egg, the command reports the carrier state.

### `/dragonegg status`

Shows the current Dragon Egg status.

### `/dragonegg reset`

Admin command.

Marks the current egg as obsolete and makes the next dragon kill drop a new Dragon Egg.

## Dragon Egg States

Known states include:

- `WAITING_DRAGON`
- `DROPPED`
- `PLACED`
- `CARRIER`
- `UNKNOWN`

## Dragon Egg Restrictions

The project includes mixins related to Dragon Egg containment and dropping.

These are intended to prevent the egg from being hidden too easily or removed from the intended gameplay loop.

Relevant classes include:

- `DragonEggContainerProtectionMixin`
- `DragonEggShulkerSlotProtectionMixin`
- `PlayerDropProtectionMixin`

## Persistence

The mod saves and loads claim data when the server starts and stops.

Claim persistence is handled by:

- `ClaimStorage`

The Dragon Egg system also persists its state.

This allows the server to keep long-term protection and gameplay state across restarts.

## Technical Architecture

Main packages:

### `claim/`

### `command/`

Player and admin commands.

### `event/`

Protection event handlers for blocks, fluids, entities, villagers, PvP, and arena behavior.

Low-level protection hooks for cases that cannot be handled cleanly with regular events.

Claim boundary visualization system.

## Important Design Decisions

### PvE by default

Survival gameplay is protected by default.

Players should not need to opt out of danger to avoid griefing or unwanted PvP.

### PvP only in arenas

PvP is intentionally limited to designated arenas.

This avoids breaking normal survival gameplay.

### Global PvP removed

A global PvP opt-in system was tested and removed.

The old system included `/pvp on`, `/pvp off`, player name colors, combat tags, and logout punishment.

That design was abandoned because it made normal survival gameplay more complicated and less vanilla-friendly.

### Villagers are protected assets

Villagers are treated as important player/server assets.

Protecting them is required for a stable survival economy.

### Claims are dimension-aware

Claims are isolated by dimension.

A claim in one dimension does not accidentally protect or conflict with another dimension.

### Server regions are first-class

The mod supports admin-created server claims, coliseums, and arenas.

This allows the server to host events and public builds safely.

## Known Limitations

- The system is designed specifically for the MundoZ server.
- Some behavior is tightly coupled to MundoZ gameplay rules.
- Admin tools are command-based rather than GUI-based.
- Dragon Egg gameplay is still evolving.
- Arena systems may need more balancing and polish.
- Public documentation may lag behind production behavior if the server changes quickly.
